---

IP Intelligence endpoints accept one IPv4 or IPv6 address and return focused enrichment data.

```json
{
  "ip": "8.8.8.8"
}
```

---

## Endpoint groups

| Operation | Endpoint | Notes |
|---|---|---|
| All | `POST /tools/ip-intelligence/all` | Runs the main IP intelligence collectors in parallel. |
| Geo | `POST /tools/ip-intelligence/geo` | Country, region, city, coordinates, timezone, and network hints. |
| Network | `POST /tools/ip-intelligence/network` | ASN, ISP, organization, reverse hostname, proxy/mobile/hosting flags. |
| BGP | `POST /tools/ip-intelligence/bgp` | Prefix, ASN, allocation, and PTR data from routing sources. |
| WHOIS | `POST /tools/ip-intelligence/whois` | Registration, range, contacts, and registry metadata. |
| RDNS | `POST /tools/ip-intelligence/rdns` | Reverse DNS hostnames. |
| Risk | `POST /tools/ip-intelligence/risk` | Lightweight risk score and labels. |
| Ports | `POST /tools/ip-intelligence/ports` | Open port, tag, CPE, hostname, and vulnerability hints. |
| Reputation | `POST /tools/ip-intelligence/reputation` | Blocklist, malicious URL, and threat reputation signals. |
| Hosted Domains | `POST /tools/ip-intelligence/hosted-domains` | Reverse IP hosted-domain lookup. |

---

## Fast path

Use `/all` when you need a complete IP profile.

```bash
curl -X POST "https://api.osint.ly/tools/ip-intelligence/all" \
  -H "Authorization: Bearer $OSINTLY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "ip": "8.8.8.8" }'
```

Use a focused endpoint when you only need one signal group.

```bash
curl -X POST "https://api.osint.ly/tools/ip-intelligence/ports" \
  -H "Authorization: Bearer $OSINTLY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "ip": "8.8.8.8" }'
```

---

## Availability

Some enrichment sources may return partial data or no data for an IP address. Tool endpoints normalize missing data to empty arrays or `null` values where possible.

---

## Latency behavior

The `/all` endpoint launches top-level collectors in parallel. Some collectors still have internal dependencies, such as reputation checks that aggregate multiple sources.

Use focused endpoints for latency-sensitive interfaces or when rendering one card at a time.
