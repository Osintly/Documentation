The Search page lets you enter an identifier and select its type. Full searches query the relevant providers in parallel, with results streaming as each source responds. Without an app subscription, you can run a [limited free preview](/guides/free-searches) for a pseudonym or email address.

<Warning>
**For domain and IP investigation, use [Domain Intelligence](/tools-reference/domain-intelligence) and [IP Intelligence](/tools-reference/ip-intelligence).** These types remain accepted by the Search API for now, but **support there will end soon**.
</Warning>

## Input types

Each input type maps to a dedicated set of providers. Select the one that matches your identifier.

<Tabs>
  <Tab title="Pseudonym">
    **What to enter:** A username or handle, exactly as it appears on the platform.

    **What it looks up:** Social profiles, forum accounts, registered services, leak databases.

    **Tips:**
    - Capitalization may matter. Enter the handle as you found it.
    - Do not include `@` unless it is part of the handle itself.
    - If the username appears in breaches, linked emails are often surfaced in the results - use them to pivot to an Email Address search.
  </Tab>
  <Tab title="Email Address">
    **What to enter:** A full email address (`user@domain.com`).

    **What it looks up:** Breach records, registered accounts, social profiles, leak databases.

    **Tips:**
    - The **Registered Accounts** panel is only available on email searches.
    - If the email uses a custom domain, pivot to [Domain Intelligence](/tools-reference/domain-intelligence) to investigate its infrastructure.
    - Multiple breaches with different associated usernames are a strong signal - search each username separately.
  </Tab>
  <Tab title="IP Address">
    **What to enter:** An IPv4 or IPv6 address.

    **What it looks up:** Geolocation, ASN, hosting provider, threat intelligence signals.

    **Tips:**
    - Results include the map view when location data is available.
    - For a focused infrastructure lookup, use [IP Intelligence](/tools-reference/ip-intelligence). The Search page may redirect IP input to that tool.
  </Tab>
  <Tab title="Domain">
    **What to enter:** The root domain (`example.com`). Full URLs are also accepted - Osintly extracts the root domain automatically.

    **What it looks up:** DNS records, WHOIS, subdomains, linked IPs, risk signals.

    **Tips:**
    - Do not include `https://` or a trailing path - or paste the full URL and let Osintly parse it.
    - Subdomains are discovered in the result, not entered manually.
    - For a focused infrastructure lookup, use [Domain Intelligence](/tools-reference/domain-intelligence). The Search page may redirect domain input to that tool.
  </Tab>
  <Tab title="Cryptocurrency">
    **What to enter:** A full wallet address.

    **What it looks up:** Transaction history, linked wallets, risk and fraud signals.

    **Tips:**
    - Osintly auto-detects the chain based on address format (Bitcoin, Ethereum, and others). For ambiguous formats, select the chain manually.
    - Shortened or partial addresses may return no results.
    - Supported chains vary by provider.
  </Tab>
</Tabs>

## Input type detection

Osintly auto-detects the input type as you type. The type chip updates based on the format of the identifier - email pattern, IP format, domain structure, wallet prefix, and so on.

You can override the detected type by clicking a different chip. An unsupported type may still appear in the selector, but the service rejects it at launch.

## Running a search

<Steps>
  <Step title="Go to the Search page">
    Navigate to [osint.ly/search](https://osint.ly/search). It is the default landing page after login.
  </Step>
  <Step title="Enter the identifier">
    Type or paste the value into the input field. The input type chip updates automatically as you type.
  </Step>
  <Step title="Adjust search options if needed">
    Click the options icon next to the search input to configure modules, leak sources, dorking, and display preferences before launching.
  </Step>
  <Step title="Launch the search">
    Click **Start search** to run a full search. Results stream in as providers respond, and a successfully launched full search costs 1 credit. Without a paid app plan, use **Run free preview** for a pseudonym or email; it has separate limits and does not use credits.

    <Note>Opening a past result from history does not run a new query and does not consume credits.</Note>
  </Step>
</Steps>

## Search options

Configure search behavior before launching from the options panel next to the input field.

<AccordionGroup>
  <Accordion title="Module selection" icon="sliders">
    Select exactly which modules should run for the current query.

    - Search modules from a dedicated input field
    - If no module is selected, Osintly runs the default module set for the chosen input type
    - If one or more modules are selected, execution is restricted to that selection

    Use this when you want to narrow execution to a specific subset of sources.
    It is useful for targeted checks, signal confirmation, and reducing noise before analysis.

    <Tip>For API usage, map this behavior to `modules` in [Search request fields](/api-reference/domains).</Tip>
  </Accordion>
  <Accordion title="Leak sources" icon="database">
    Toggle which leak and breach provider categories are included in the search. Disabling a category means those providers are not queried and their cards do not appear in results.

    Options that exceed your plan are shown but disabled.
  </Accordion>
  <Accordion title="Dorking engine" icon="code">
    Enable OSINT dorking to surface results from indexed public sources using structured search queries. Useful for pseudonym and domain searches where surface-level indexed data may add context.
  </Accordion>
  <Accordion title="Open in new tab" icon="arrow-up-right-from-square">
    Opens the result page in a new browser tab instead of navigating away from the Search page. Useful when running multiple searches in quick succession.
  </Accordion>
  <Accordion title="Mask query" icon="eye-slash">
    Hides the search term from the browser tab title and page heading. The search runs normally - only the visible label is masked. Useful when working in environments where screen visibility is a concern.
  </Accordion>
</AccordionGroup>

## CrossSearch

CrossSearch is available on **Pro and Ultimate**. It automatically searches compatible profiles linked from your result cards, keeping each discovery attached to its source card. Open the stack next to a source card to see the linked results.

CrossSearch is enabled by default for eligible app searches. Use the **CrossSearch** switch next to the credits in the search box, or change it under **Settings → Search results → CrossSearch**. Both controls share the same saved preference. Standard and free previews do not include it. Organization searches use the organization’s Pro or Ultimate plan.

For API searches, CrossSearch is **disabled by default** and must be enabled with `features.crosssearch: true`; see [Create Search](/api-reference/endpoint/search).

## Temporary search

Use temporary search when a search should not be kept in Osintly. Click the clock in the top-right corner of the Search page to turn it on. The heading changes to **Temporary search**, the search box gets a dashed border, and a note replaces the project selector.

A temporary search:

- Shows its results only in the current tab. They disappear when you refresh or close the tab, or when you start another search.
- Is not saved to History or to a project, so it cannot be reopened or shared.
- Does not store its results or reuse cached results: every provider is queried fresh.
- Does not include the AI Analyst, card annotations, collaboration, or exports, and does not save your result filters.
- Pauses product analytics and session recording while the mode is on.
- In an organization, appears in the [activity log](/collaboration/organization-activity) as **Ran a temporary search**, with the member, time, and search type. The searched value and results are never recorded.
- Costs 1 credit, like a full search.

Temporary search is available on paid app plans, including organization plans, and not on free previews. The mode stays on in your browser until you turn it off, including after a reload. To open the Search page directly in this mode, use [osint.ly/search?temporary=true](https://osint.ly/search?temporary=true).

For API searches, use `POST /search/temporary`; see [Temporary Searches](/api-reference/temporary-searches).

## Plan limits

Provider coverage depends on your plan. Standard queries a base set of providers. Pro and Ultimate unlock additional sources, including premium breach databases and extra leak providers. For full pricing details, see [osint.ly/pricing](https://osint.ly/pricing).
 

| Capability | Standard | Pro | Ultimate |
|---|---:|---:|---:|
| Monthly credits included | 25 | 100 | 200 |
| Pseudonym search | Yes | Yes | Yes |
| Email Address search | Yes | Yes | Yes |
| IP Address search | Yes | Yes | Yes |
| Domain Name search | No | Yes | Yes |
| Cryptocurrency search | No | Yes | Yes |
| CrossSearch | No | Yes | Yes |
| Temporary search | Yes | Yes | Yes |
| Leak sources | No | Yes | Yes |
| AI Analyst | No | Yes | Yes |
| Monitoring & Alerts | No | See current product availability | See current product availability |
| Organization members | — | Plan and paid seats determine access | Plan and paid seats determine access |
| Result sharing | No | No | Yes |
| Export (PDF / JSON / CSV / Markdown) | Yes | Yes | Yes |
| Priority support | No | No | Yes |

If a provider is not available on your plan, its card does not appear in results and related options are disabled in search settings. These paid-plan limits do not describe [free previews](/guides/free-searches).

## Search history

Full app searches are saved automatically in the workspace selected when they launch. Access them through [History](/guides/history). Personal history stays private; organization history is shared with the organization’s members and identifies the creator. Free previews are temporary and do not appear there, and [temporary searches](#temporary-search) are never saved.

From the history page you can:
- Re-open any past result at no credit cost
- Delete individual entries
- Select and delete multiple entries at once

<Tip>Use history to resume an investigation without spending credits. Re-open a cached result, then run a fresh search only when you need updated data.</Tip>
