## Core entities

| Entity | Purpose | Key fields |
|---|---|---|
| Search | One launched search execution | `id`, `type`, `value`, `status`, `created_at`, `user_id`, `organization_id`, `project_id`, `team_id`, `search_metadata` |
| Search Result payload | Stored final payload attached to a search | `result.cards[]`, `result.leaked_data`, `result.breached_accounts[]`, `result.registered_accounts[]` |
| Stream event | Incremental event consumed by the result page | `taskId`, `moduleId`, `moduleName`, `result`, `timestamp`, `status` |
| Monitor (legacy) | Scheduled monitoring definition being retired | `id`, `user_id`, `name`, `type`, `target`, `frequency`, `status` |
| Monitoring Alert (legacy) | Alert emitted by the retiring monitor processor | `id`, `user_id`, `monitor_id`, `severity`, `message`, `status`, `created_at` |
| Tool result | Saved focused lookup | `id`, `tool_slug`, `title`, `query`, `created_at`, `user_id`, `organization_id` |
| Organization | Shared paid workspace | `id`, `name`, `status`, subscription and paid-seat context |
| Organization Membership | User role inside an organization | `organization_id`, `user_id`, `role` (`owner`, `admin`, `member`) |
| Organization Invitation | Pending organization access | `organization_id`, `email`, `role`, invitation state, seat reservation |
| Project | Personal or legacy Team investigation workspace | `id`, `title`, `description`, `content`, `owner_id`, `team_id`, `created_at`, `updated_at` |
| Team (legacy) | Historical collaboration boundary | `id`, `owner_id`, `name`, legacy credit-policy fields |

## Search and module states

<Tabs>
  <Tab title="Search status">
    Typical status flow:

    - `pending`
    - `running`
    - `finished`
    - `error`
  </Tab>
  <Tab title="Module delivery">
    Module outputs are delivered as independent stream events. Cards can arrive in any order and are merged on the client as events are received.
  </Tab>
  <Tab title="Panel updates">
    Synthesis panels are client-computed from available card/result data and only render when relevant data exists.
  </Tab>

## Visibility rules

A field, tab, or panel is displayed only when all required conditions are met:

1. The search type supports that view
2. The plan allows the underlying data source
3. Matching data is present in returned payloads
4. The user has not disabled the view in display settings

<Note>
Missing panel usually means no applicable data was returned, not a rendering issue.
</Note>

## Relationships in practice

<AccordionGroup>
  <Accordion title="Search -> Module Results" icon="link">
    One search execution yields multiple module outputs (stream events and/or stored cards).
  </Accordion>
  <Accordion title="Search -> Result payload" icon="chart-simple">
    One search can include cards plus optional leaked, breached, and registered account datasets in its stored result payload.
  </Accordion>
  <Accordion title="Organization -> Searches and tool results" icon="buildings">
    An organization owns searches and saved tool results launched while it is selected. The launching member remains recorded as the creator.
  </Accordion>
  <Accordion title="Legacy Team -> Projects -> Searches" icon="users">
    Legacy Teams group projects, and projects can reference saved searches, notes, and attachments. They do not overlap with organization scope.
  </Accordion>
  <Accordion title="Legacy Monitor -> Alerts" icon="bell">
    The retiring Monitoring experience can contain alert records with their own workflow status. New Security Watch guidance will be published separately.
  </Accordion>
</AccordionGroup>
